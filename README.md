# DS3Probe v4

Прокси `dinput8.dll` для Dead Space 3 (Win32). **Ничего не чинит**: собирает данные и по клавишам F9/F11 подменяет вход игры, чтобы найти, где именно ставится потолок скорости поворота камеры («чем быстрее рвёшь мышь, тем меньше эффект, а после порога поворот всегда одинаковый»).

Статус и допущения: `claude/ds3_status.md`. Аудит: `claude/ds3_audit_2026-10-07.md`.

## Зачем v4 (что показали данные v3, сессия 20261007_194254)

1. **Эталон Raw Input в v3 был мёртв** (в `raw_dx` везде нули): DirectInput игры перерегистрировал мышь процесса, и проба лишилась своего потока `WM_INPUT`. Вердикт анализатора «резких движений нет» был артефактом. В v4 эталоном служат счёты DirectInput, проба Raw Input сама не регистрирует и только пишет в лог, кто его регистрирует.
2. **DirectInput и курсорный аккумулятор несут один сигнал** (98 % кадров совпадают точно, отношение сумм 1.02–1.07 на скоростях 1…800 отсчётов/кадр). Сжатия и полки между рукой и этими двумя слоями нет.
3. **Камера вращалась при обнулённом аккумуляторе** (`look = 0` минуту подряд). Значит, камеру питает не путь «курсор → `InputMapper_Update` → `MouseState.look`», а, скорее всего, DirectInput. Потолок сидит **после** DirectInput, внутри игры.

Отсюда режимы F9 теперь подменяют именно вход DirectInput.

## Что нужно

- Игра **1.0.0.1** (MD5 `1802f17a2cc1c2797323632862c6fb1f`). Адреса зашиты в DLL по MD5: **cfg не нужен**. На другой сборке exe-хуки не ставятся (user32/DirectInput работают).
- DLL из артефакта GitHub Actions (`DS3Probe-<sha>`): `dinput8.dll`, `README.md`, `ds3probe.cfg.example`, `analyze_di.py`, `DS3_DiConsumers.py`. В репозитории они лежат в `tools/` и `ghidra/`.
- Установка: `dinput8.dll` в папку с `deadspace3.exe` (заменить v3). Удаление: удалить файл.

## Первый запуск: что должно быть в логе

Лог: `ds3probe_logs\<дата_время>\ds3probe.log` (`latest.txt` указывает на последнюю папку). Каждая сессия — своя папка.

| строка в логе | норма |
|---|---|
| `DS3Probe v4 sha=... attach` | v4, а не v3 |
| `exe MD5=1802f17a...` и `profile: 1.0.0.1 selected by MD5` | оба есть |
| `anchor: OK: ... confirms Mouse_GetState=0040A820` | допустим `FAILED`; `MISMATCH` — хуки Mouse_GetState отключены |
| `Mouse_GetState / Mouse_WndMsg / InputMapper_Update hook: ok` | как в v3 |
| `StickVirt hook: ok`, `StickSmooth hook: ok` | **новое.** `FAILED` — байты функций не совпали, F11 недоступна, `_stickv/_sticks.csv` не будут писаться |
| `exe hooks done: ... stickVirt=1 stickSmooth=1 traces=N` | N = число трассировщиков из cfg |
| `DirectInput8Create ver=... hr=0x00000000`, `hook DirectInput8Create: ok` | есть |
| `DI mouse state: cb=20 lX=... from exe+0x... [ghidra 00XXXXXX]` | **ключевая строка**: игра читает мышь через DirectInput. Пока её нет, F9 пишет `UNAVAILABLE`. Адрес «from» — вызывающий в Ghidra-координатах: это точка входа в потребителя |
| `RegisterRawInputDevices(n=...) from ...` | **новое.** Кто регистрирует Raw Input; если игра не регистрирует — строк нет |
| `1s: ... mode=PASS DI=(sumX,sumY) stickV(max out=... acc_len=... sat=N) stickS(max out=...)` | `DI` — сумма DI за секунду (печатается, когда водишь мышью); `stickV/stickS` — максимумы выходов стик-функций за секунду (появляются, если эти функции вызываются); `acc_len` → 1.0 и `sat` > 0 = упор в круговой клэмп |

## Горячие клавиши (окно игры в фокусе)

| клавиша | что делает | звук |
|---|---|---|
| F6 | маркер в лог + таблицы «кто вызывает» (user32 и DI-мышь, со стеком вызывающих) | — |
| F7 / F8 | начало / конец захвата (CSV + итоги в лог) | 1 / 2 писка |
| **F9** | режим: **PASS → DI-ZERO → DI-xA(×0.5) → DI-xB(×0.25) → DI-xC(×2.0) → ACC-ZERO → PASS** | 1 / 1 / 2 / 3 / 4 / 5 писков (PASS — один низкий) |
| F10 | условия опыта + список зарегистрированных raw-устройств | — |
| **F11** | «открыть клэмп» `FUN_0040D820` (`this[3] := 1e9` на каждом вызове) вкл/выкл | вкл 2 высоких, выкл 1 |

Режимы:

- **DI-ZERO** — `lX/lY` из `GetDeviceState` := 0. Камера обязана замереть, если она питается от DI. Если крутится — у неё другой источник.
- **DI-xA / xB / xC** — отсчёты × 0.5 / 0.25 / 2.0 (с дробным остатком, ничего не теряется). Если потолок внутри игры и он по скорости, он сдвинется пропорционально K; если потолок по углу за время, поворот на рывке не изменится.
- **ACC-ZERO** — обнуляется курсорный аккумулятор (путь v3). Нужен только для сверки: камера должна вращаться как обычно.
- **F11** — снимает клэмп `±this[3]` в сглаживателе стика. Исчез потолок — причина найдена; не исчез — потолок в другом месте (смотри трассировщики).

Страховка: режимы F9 сами возвращаются в PASS через 2 минуты. Подмена касается только отсчётов мыши, игру не ломает.

## Вечерний протокол (1.0.0.1, ~30–40 минут, 75 Гц как у тебя)

Одинаковые движения во всех захватах. Набор движений («пакет»), паузы между ними > 0.3 с:

- 10 медленных проводок (≈ полэкрана за секунду);
- 10 **коротких рывков** (≈ 4–5 см за ~0.1 с);
- 10 **длинных рывков** (≈ 15 см за те же ~0.1 с).

Твоё наблюдение «одно и то же время → один и тот же поворот независимо от дистанции» проверяется именно парой «короткий / длинный рывок». Запиши на глаз, одинаков ли угол.

| # | действия | что записать |
|---|---|---|
| 1 | Вошёл в геймплей. **F6** (маркер + стек вызывающих DI-мыши). F10 | — |
| 2 | **A. PASS:** F7 → пакет → F8 | угол короткого и длинного рывка: равны / длинный больше |
| 3 | **B. DI-ZERO:** F9 (1 писк) → F7 → 3 с водить мышью → F8 | **крутится ли камера** (главный вопрос) |
| 4 | **C. DI-xA (×0.5):** F9 (2 писка) → F7 → пакет → F8 | медленные проводки в 2 раза «короче»? рывки: угол тот же или в 2 раза меньше? |
| 5 | **D. DI-xC (×2):** F9 два раза (до 4 писков) → F7 → пакет → F8 | угол рывка тот же / в 2 раза больше? есть ли «новый потолок»? |
| 6 | F9 до PASS (либо подожди 2 минуты) | — |
| 7 | **E. открытый клэмп:** F11 (2 высоких писка) → F7 → пакет → F8 → F11 (выкл) | **исчез ли потолок** (длинный рывок теперь больше короткого?) |

Что прислать: папку `ds3probe_logs\<сессия>` целиком (лог + все CSV) и ответы в колонке «что записать».

Если нужно меньше: достаточно шагов 1–3 и 7. Шаги 4–5 важны, чтобы отличить «потолок по скорости» от «потолок по углу за время».

## Анализ

```
python analyze_di.py ds3probe_logs\<сессия>
```

(`analyze_samples.py` — анализатор v3; для данных v4 не нужен.) Блоки:

- **[A]** DI против курсорного пути: совпали ли кадры, сдвиг, отношение сумм по скоростям.
- **[B]** режимы: сработала ли подмена (`out/game ≈ K`, ZERO ≈ 0).
- **[C]** передаточная кривая «вход DI → выход стика» по корзинам скорости; вердикт «линейна / сжатие / ПЛАТО».
- **[D]** выход стика при DI-ZERO / DI-xK: питается ли стик от DI.
- **[E]** трассировщики: число вызовов, адреса возврата.

Самопроверка анализатора на синтетике: `python tests/test_analyze_di.py` (в Actions идёт отдельным шагом и сборку DLL не блокирует).

### Как читать итог

| наблюдение | вывод |
|---|---|
| DI-ZERO: камера замерла | камера питается от DI; потолок между DI и камерой |
| DI-ZERO: камера крутится | есть другой источник (Raw Input? клавиатурная эмуляция?) — смотри строки `RegisterRawInputDevices` и трассировщики |
| xA/xC: угол рывка пропорционален K | потолка по скорости нет; сжатие — в самом коэффициенте/кривой |
| xA/xC: угол рывка не меняется | потолок по углу (клэмп результата или лимит скорости поворота) |
| F11: потолок исчез | причина — клэмп `±this[3]` в `FUN_0040D820`; фикс = менять `this[3]` или обходить клэмп |
| F11: потолок остался | клэмп не тот; [C] по `_stickv.csv`: длина `acc` упирается в 1.0 → `FUN_0040E680` (круговой клэмп) |
| [C]: `ПЛАТО` на выходе стика, на входе линейно | потолок в конвейере «стик»; координаты — в `_sticks.csv` |
| [C]: стик линеен, а камера всё равно упирается | потолок в потребителе стика (камера/лимит скорости поворота): трассировщики на потребителей |

## Трассировщики (новые гипотезы без пересборки)

В `ds3probe.cfg` (см. `ds3probe.cfg.example`): `Trace1 = <адрес из Ghidra>`, `Trace1.bytes = <первые 8+ байт из Ghidra>`, `Trace1.name = подпись`. Хук ставится на вход функции, пишет `ecx`, `edx`, аргументы стека и поля `this` в `ds3probe_cap_NNN_trace.csv` и в лог. Хук ставится, только если байты совпали.

## Ghidra (на работе)

1. `ghidra\DS3_DiConsumers.py` на **1.0.0.1**: ищет вызовы `CALL [reg+0x24]` (GetDeviceState) с размером буфера 0x14/0x10 перед вызовом, перечисляет вызывающих, глобальные буферы и читателей, декомпилирует; в конце — потребители `FUN_0040E680 / FUN_0040D820 / FUN_00ABC510`. Результат: `~/ds3_di_consumers_1802f17a.md`. Положи в проект.
2. Адрес «from» в строках `DI mouse state:` и `DI mouse GetDeviceState callers:` лога пробы — тот же потребитель; сверь его с отчётом скрипта.
3. Если отчёт покажет, что `GetDeviceState` вызывается через обёртку и размер не константа — смотри таблицу «размер неизвестен» и стек вызывающих из F6.

## Файлы сессии

- `ds3probe.log` — лог (строки `1s:` раз в секунду).
- `ds3probe_cap_NNN_di.csv` — кадры DI-мыши: `t_ms,raw_dx,raw_dy,game_dx,game_dy,mode,out_dx,out_dy` (`game_*` — что отдал DI, `out_*` — что получила игра после подмены; `raw_*` в v4 не используется).
- `ds3probe_cap_NNN_acc.csv` — кадры `Mouse_GetState` (курсорный путь, как в v3), с кодом режима.
- `ds3probe_cap_NNN_stickv.csv` — вызовы `FUN_0040E680` (виртуальный стик): `x_out,y_out,acc_x,acc_y,active,id`.
- `ds3probe_cap_NNN_sticks.csv` — вызовы `FUN_0040D820`: `dt,x_in,y_in,x_out,y_out,win,blend,clamp,active,w0..w7,ret_hex`.
- `ds3probe_cap_NNN_trace.csv` — трассировщики из cfg.

## Что не проверено (честно)

- **DLL v4 не собиралась автором** (нет Windows-тулчейна): проверен только разбор clang (`-fsyntax-only`) с самодельными заглушками заголовков. Ошибка Actions — пришли текст.
- Соглашения вызова `FUN_0040E680` и `FUN_0040D820` (`__thiscall`, порядок аргументов) взяты из декомпиляции Ghidra и могут быть неточными; в логе первые вызовы печатаются, значения должны быть правдоподобными (`dt` ≈ 0.013, `id` 4 или 5, выход в пределах ±1).
- Что стик-функции вообще участвуют в клавиатурно-мышиной камере — **гипотеза**: `id` в рантайме 4/5 (< 0x10), тип устройства KBM (0x12). Если `_stickv/_sticks.csv` пусты или `active=0` — они обходятся, это тоже ответ.
- Режимы DI подменяют только `GetDeviceState` для мыши (`cb=20`). Если игра читает `GetDeviceData`, подмена не сработает: в логе не будет `DI mouse state` и F9 напишет `UNAVAILABLE`.
- `this = ecx` в `InputMapper_Update` и смещения `+0x17C`/`+0x18C` — из 1.0.0.0; самопроверка в логе.
