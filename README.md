# DS3Probe v3

Прокси `dinput8.dll` для Dead Space 3 (Win32). **Ничего не чинит**: собирает данные и по клавише F9 подменяет вход игры, чтобы понять, на каком участке пути «мышь → камера» теряется движение («отрицательное ускорение»).

Основа: аудит проекта от 2026-10-07 (`claude/ds3_audit_2026-10-07.md`), раздел 6. Статус и все допущения: `claude/ds3_status.md`.

## Что нужно

- Игра **1.0.0.1** (MD5 `1802f17a2cc1c2797323632862c6fb1f`). Для неё адреса зашиты в DLL по MD5 exe: **cfg создавать не нужно**. На другой сборке exe-хуки сами не ставятся (user32/DirectInput/Raw Input работают).
- DLL берётся из артефакта GitHub Actions (`DS3Probe-<sha>`): внутри `dinput8.dll`, `README.md`, `ds3probe.cfg.example`, `analyze_samples.py`.
- Установка: `dinput8.dll` в папку с `deadspace3.exe`. Удаление: удалить файл.

## Первый запуск: что должно быть в логе

Лог: `ds3probe_logs\<дата_время>\ds3probe.log` рядом с exe (`ds3probe_logs\latest.txt` указывает на последнюю папку). Если папка игры недоступна для записи (Program Files), всё пишется в `%TEMP%\ds3probe_logs`. Каждая сессия — своя папка, ничего не затирается.

Проверь по порядку (после входа в геймплей):

| строка в логе | норма |
|---|---|
| `DS3Probe v3 sha=...` | sha совпадает с коммитом, из которого собрана DLL |
| `exe MD5=1802f17a... PE TimeDateStamp=...` | MD5 совпадает; иначе `profile: none` и exe-хуков не будет |
| `profile: 1.0.0.1 selected by MD5` | есть |
| `anchor: OK: ... confirms Mouse_GetState=0040A820 independently` | **независимое подтверждение адреса.** `FAILED` допустимо (экспорт мог измениться), `MISMATCH` — хуки Mouse_GetState отключены |
| `Mouse_GetState ... hook: ok`, `Mouse_WndMsg hook: ok`, `InputMapper_Update hook: ok` | все `ok` |
| `exe hooks done: Mouse_GetState=1 acc=1 F9-modes=available` | режимы F9 доступны |
| `WndMsg #1: msg=0x...` | значения похожи на `WM_*` (0x200, 0x20, 0x84, 0x215…). Если мусор — раскладка стека другая, парность raw/game упадёт в `direct` |
| `InputMapper #1: this=... sens@+17C=... MouseState=... look=...` | `sens` в диапазоне 0.1…1.9. Если в логе `MouseState capture DISABLED` — смещения (`OffSens`, `OffMouseState`) или `this` не те |
| `mgr=...: [mgr+0x540]=... vs MouseState=... (EQUAL / different)` | проверка гипотезы аудита 2.1; любой исход — данные |
| `1s: ... MouseGetState=N ...` | N ≈ FPS игрового цикла |

## Горячие клавиши (окно игры в фокусе)

| клавиша | что делает | звук |
|---|---|---|
| F6 | маркер в логе + таблица «кто вызывает GetCursorPos/SetCursorPos/ClipCursor/ShowCursor» | — |
| F7 / F8 | начало / конец захвата (CSV + итоги в лог) | 1 / 2 писка |
| **F9** | режим входа: **PASS → RAW → ZERO → PASS** | 1 / 2 / 3 писка |
| F10 | записать условия опыта в лог | — |

Режимы (подмена на входе `Mouse_GetState`, до чтения аккумулятора игрой):

- **PASS** — игра как есть (по умолчанию после каждого запуска).
- **RAW** — аккумулятор := счёты Raw Input × `RawScale` (по умолчанию 1.0). Это источник без курсора Windows, без центровки и без полки.
- **ZERO** — аккумулятор := 0. Если камера всё равно вращается, у неё есть другой источник (не этот путь).

Страховка: RAW/ZERO сами возвращаются в PASS через 2 минуты. Игру подмена не ломает: пишется только int-аккумулятор мыши.

## Вечерний протокол (1.0.0.1, ~40 минут)

**Шаг 0. Два бесплатных теста, до всяких измерений (10 минут).** Один и тот же резкий разворот на одинаковую дистанцию, оценка «лучше / так же / хуже»:

1. `control.MouseSmoothing = false` в `%LOCALAPPDATA%\EA Games\Dead Space 3\general.txt` (источник: PCGamingWiki). Если ключа нет в файле — добавь строку; если игра её стирает или не читает, запиши «ключ не действует».
2. Зависимость от FPS: лимит 30 (встроенный V-sync или RTSS), 60, без лимита. Запиши реальный FPS (оверлей RTSS). Полка до аккумулятора предсказывает «хуже при низком FPS»; «плавающая» мышь из вики — «хуже при высоком».

**Шаг 1. Запуск пробы**, проверка лога по таблице выше.

**Шаг 2. Три захвата с одинаковыми движениями** (одинаковый FPS-лимит для всех трёх; начни с 30, если останется время — повтори на 144/без лимита):

| захват | действия |
|---|---|
| A. PASS | F7 → 10 медленных проводок (≈ полэкрана за секунду) + 10 резких рывков на всю ширину коврика, между движениями пауза > 0.3 с → F8 |
| B. RAW | F9 (2 писка) → F7 → те же движения → F8. **Оцени ощущение**: пропало ли «отрицательное ускорение» |
| C. ZERO | F9 (3 писка) → F7 → 3 секунды водить мышью → F8. **Запиши, вращается ли камера** |

После C нажми F9 (1 писк = PASS). Если в RAW чувствительность другая, возьми в логе PASS-захвата `game/raw path=…` и задай `RawScale` в cfg.

**Шаг 3. Что прислать:** папку `ds3probe_logs\<сессия>` целиком (лог + CSV) и `general.txt`. Положи в проект Claude.

## Анализ

```
python analyze_samples.py ds3probe_cap_001_acc.csv ds3probe_cap_002_acc.csv
```

Скрипт читает шапку CSV (клиентская область, половина `half`), делит на уровни и печатает вердикт:

- **Уровень 1, raw → game:** есть ли полка (за кадр игра получает не больше половины ширины клиентской области) и зависит ли ratio от скорости.
- **Уровень 2, out → look:** линеен ли `InputMapper_Update` (look/out по корзинам, запаздывание look подбирается).
- **Режимы:** `out/raw` в RAW ≈ `RawScale`; в ZERO look ≈ 0.
- Уровень 3 (`look` → камера) в CSV не виден.

Самопроверка анализатора на синтетических данных: `python tests/test_analyze.py`.

### Как читать итог

| наблюдение | вывод |
|---|---|
| Полка найдена, в RAW «ускорение» ушло | потеря до аккумулятора; фикс первого уровня: подмена источника в `Mouse_GetState` |
| Полки нет, уровни 1–2 линейны, в RAW то же самое | причина в потребителе `MouseState` (камера: сглаживание, лимит скорости поворота, множитель frame time). Идти по зацепкам аудита раздела 7 |
| Уровень 2 нелинеен | причина внутри `InputMapper_Update`/`MouseState` |
| В ZERO камера вращается | у камеры есть другой источник (DI-мышь?); смотреть `_di.csv` и `FUN_008912c0` |
| `pairing=direct` в шапке | хук `Mouse_WndMsg` не работает: покадровые таблицы шумные, суммы и всплески остаются верными |

## Файлы сессии

- `ds3probe.log` — лог. Строки `1s:` — раз в секунду: счётчики вызовов, `raw=(x,y)`, `acc=(x,y)`, `mode`, `look`, `sens`, `cap`/`rc`.
- `ds3probe_cap_NNN_acc.csv` — кадры `Mouse_GetState`: `t_ms,raw_dx,raw_dy,game_dx,game_dy,mode,out_dx,out_dy,look_x,look_y,sens,cap,rc`; шапка из строк `# ...` (условия опыта).
- `ds3probe_cap_NNN_di.csv` — то, что игра получила от DirectInput-мыши (если читает её через `GetDeviceState`).

## Что не проверено (честно)

- **DLL не собиралась автором**: в его среде нет Windows-тулчейна. Проверен только разбор clang (`-fsyntax-only`) с самодельными заглушками заголовков; настоящую сборку делает Actions. Ошибка компиляции — пришли текст.
- `this = ecx` в `InputMapper_Update` и смещения `+0x17C`/`+0x18C` взяты из 1.0.0.0; на 1.0.0.1 их подтверждает или опровергает самопроверка в логе.
- `AccDY = AccDX + 4` из декомпиляции (оба по соседству), якорь проверяет только `AccDX`.
- Заглушки «рабочих имён»: `FlagCaptured`, `FlagRecenter`, `VirtW/H`, `MgrPtr` читаются только для лога/условий.
- Режим RAW заменяет **только** аккумулятор; курсор Windows по-прежнему центруется игрой.
