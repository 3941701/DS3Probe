# DS3Probe v4.10

Прокси `dinput8.dll` для **Dead Space 3 1.0.0.1** (Win32). Исправляет управление камерой мышью и оставляет при себе инструменты, которыми причины были найдены: запись захватов, трассировщики функций игры, ловец писателей памяти, анализаторы.

Состояние: активная разработка завершена, результат принят в игре (v4.9, запись `20261009_225325`). Дальше только исправление ошибок, если они появятся. v4.10 добавляет ключ `LookPitch` (вертикаль обычной камеры, проверяется на ощупь) и мелкие исправления из раздела 9.2 паспорта. Полный технический паспорт (модель камеры, замеры, подтверждённые и опровергнутые гипотезы, открытые вопросы) хранится в файлах проекта: `ds3_architecture_snapshot_2026-10-11.md`.

## Что исправляет

| проблема в игре | причина (найдена) | исправление | ключ cfg |
|---|---|---|---|
| Инерция камеры (~130 мс), «рикошёт» на быстрых рывках | внешний кадр камеры `FUN_0074D6F0` смешивает ориентацию с прошлым кадром с весом `7.5·dt` (~0.1 за кадр), смешивание идёт по кратчайшей дуге, и при отставании больше 180° угол дёргается назад | на входе `LookUpdate` каждый кадр переписываются `ctrl+0x13C/0x140`, вес смешивания становится 1 (или `1-exp(-dt/tau)`) | `FollowFix = 1` (F4) |
| Потолок скорости поворота на рывках | сглаживатель стика `FUN_0040D820` режет сумму окна до `±2.0` | `this[3]` сглаживателя := 1e9, отклик линейный | `StickClamp = 1000000000` (F11) |
| В невесомости горизонталь в 2.15 раза медленнее, чем на земле | своё усиление 1.8326 рад/с на единицу стика (на земле yaw 3.940) | выход сглаживателя умножается только для вызова из кода свободного полёта (`0054F806`) | `ZeroGYaw = 2.15` |
| Вне прицела вертикаль «зыбкая»: в 2.15 раза медленнее горизонтали (на магнитной поверхности в 3 раза), в прицеле разница всего 1.25 | кривая чувствительности игры даёт горизонтали x2.149, вертикали x1.0 (при ползунке 50); у магнитной поверхности поле скорости pitch 2.5° вместо 3.5° | вертикаль выхода сглаживателя умножается только для вызова обычной камеры (`0073F407`); подбирается на ощупь (ГИПОТЕЗА, что дело в этом) | `LookPitch = 2.15` (F2) |
| В прицеле чувствительность «плавает» и «подлипает» | игра разгоняет усиление прицела, пока стик больше 1: yaw до x2, pitch до x4 | аргументы `ApplyRotDelta` из кода прицела подменяются на значения с множителем 1 (100°/с yaw, 80°/с pitch на единицу стика) | `AimLinear = 1` |

Курсор меню, клавиатура и геймпад не затрагиваются. С v4.10 `LookPitch`, `ZeroGYaw`/`ZeroGPitch` и `AimLinear` проверяют байт сглаживателя `+0x30` (1 = пара пришла от клавиатуры и мыши) и пару геймпада пропускают как в игре.

## Установка

1. Игра 1.0.0.1: MD5 `deadspace3.exe` = `1802f17a2cc1c2797323632862c6fb1f`. На другой сборке хуки в exe не ставятся (DLL просто пробрасывает DirectInput).
2. Скачать артефакт `dinput8` последней сборки в GitHub Actions (вкладка Actions, ветка с последним PR). В нём `dinput8.dll`, этот README, примеры cfg и анализаторы.
3. Положить `dinput8.dll` в папку с `deadspace3.exe`.
4. Положить рядом `ds3probe_play.cfg.example` под именем **`ds3probe.cfg`**. Без cfg DLL только собирает данные, исправления выключены.
5. Удаление: удалить `dinput8.dll` (и `ds3probe.cfg`).

Настройки игры, на которых всё проверялось: borderless 1920x1080, 75 Гц, около 74 FPS, ускорение мыши Windows выключено. Угол на отсчёт мыши от FPS не зависит.

## Что должно быть в логе

Лог: `ds3probe_logs\<ГГГГММДД_ЧЧММСС>\ds3probe.log` рядом с exe (`ds3probe_logs\latest.txt` указывает на последнюю папку). Каждый запуск пишет в свою папку.

| строка | норма |
|---|---|
| `DS3Probe v4.10 sha=... attach` | версия и коммит сборки (с v4.10 и у сборок из PR это голова ветки) |
| `exe MD5=1802f17a...`, `profile: 1.0.0.1 selected by MD5` | обе есть |
| `cfg: parsed, 0 error(s)` | при любой ошибке в cfg хуки в exe не ставятся, причина строкой выше |
| `StickSmooth hook: ok`, `Trace1 (ApplyRotDelta) hook: ok`, `Trace2 (LookUpdate) hook: ok` | все `ok` |
| `F4 stats (periodic): on=1 ... applied=N ... kept=N clobbered=0..` | раз в 5 с, пока обход включён; `applied` растёт в геймплее |
| `AimLinear stats (...)`, `AimLinear gain histogram ...` | после прицеливания; `skipModel` единицы на тысячи вызовов; `skipPad` 0 при игре мышью |
| `cfg: LookPitch=...`, `LookPitch: vertical of the normal camera multiplied by ...` | только если `LookPitch` не 1; вторая строка после первого движения мыши вне прицела |
| `RawInput reference: off` | норма (эталон Raw Input нужен только старым опытам, включается `RawInputRef = 1`) |

## Горячие клавиши (окно игры в фокусе)

| клавиша | действие | звук |
|---|---|---|
| F2 | ступени `LookPitch`: 1, 1.25, 1.5, 1.75, 2, 2.15 (следующая больше текущей, после 2.15 снова 1); стартует со значения из cfg; смены во время захвата пишутся в шапку CSV | 1 низкий на 1, иначе высокие: 1.25 один, 1.5 два, 1.75 три, 2 четыре, 2.15 пять |
| F3 | ловец писателей (`WatchN` в cfg): аппаратные точки останова вкл/выкл | 2 высоких / 1 низкий |
| **F4** | обход сглаживания камеры вкл/выкл (F4 выкл = игра как есть, AimLinear тоже выключается) | 2 высоких / 1 низкий |
| F5 | метка «вижу проблему сейчас» в захвате (`_marks.csv`) | 1 высокий |
| F6 | маркер в лог + таблицы вызывающих (user32, DI-мышь, сглаживатель) | нет |
| F7 / F8 | начало / конец захвата (CSV + итоги в лог) | 1 / 2 писка |
| F9 | режим подмены DirectInput (только для опытов): PASS, DI-ZERO, DI-x0.5, DI-x0.25, DI-x2, ACC-ZERO; сам возвращается в PASS через 2 минуты | по номеру режима |
| F10 | условия опыта и список зарегистрированных Raw Input устройств в лог | нет |
| **F11** | ступени клэмпа сглаживателя: 0 (значение `StickClamp` из cfg или игровое 2.0), 6, 12, 24, 1e9 | 1 низкий на 0, 2 высоких на ступенях |

## Конфигурация

DLL ищет рядом с exe `ds3probe_<md5>.cfg`, затем `ds3probe.cfg`. Разбор строгий: опечатка, неизвестный ключ или число вне диапазона отключают все хуки в exe (причина в логе). Всё после `#` комментарий.

Готовые файлы:

- `ds3probe_play.cfg.example`: для игры. Трассировщики `ApplyRotDelta` (role `aimlin`) и `LookUpdate` (role `ctrl`), `FollowFix = 1`, `StickClamp = 1e9`, `ZeroGYaw = 2.15`, `AimLinear = 1`.
- `ds3probe_camdump.cfg.example`: отладка камеры. Трассировщики с дампами объекта контроллера и блока камеры, датчик `BlendOut` (что уходит в `SetTransform`), `Watch1..4`. Исправления там закомментированы.
- `ds3probe.cfg.example`: справочник всех ключей с диапазонами.

Ключи исправлений:

| ключ | диапазон | по умолчанию | что делает | требует |
|---|---|---|---|---|
| `FollowFix` | 0/1 | 0 | обход сглаживания камеры с запуска | трассировщик `0073F310` с `.role = ctrl` |
| `FollowTauMs` | 0..2000 | 0 | 0 = камера точно в цели; больше 0 = своя постоянная времени (оригинал около 127 мс) | `FollowFix` |
| `StickClamp` | 0..1e9 | 0 (не трогать) | клэмп сглаживателя стика | хук `StickSmooth` |
| `ZeroGYaw`, `ZeroGPitch` | 0.1..10 | 1 | множитель выхода сглаживателя в свободном полёте | хук `StickSmooth` |
| `AimLinear` | 0/1 | 0 | прицел без разгона усиления | трассировщик `00721BD0` с `.role = aimlin` и включённый F4 |
| `LookPitch` | 0.1..10 | 1 | множитель вертикали мыши для обычной камеры (земля и магнитная поверхность); 2.15 = как горизонталь на земле | хук `StickSmooth` |
| `RawInputRef` | 0/1 | 0 | регистрировать мышь Raw Input как эталон (только для опытов v3/v4; до v4.10 было всегда) | нет |

Трассировщики `Trace1..Trace8`: mid-хук на любом адресе exe (координаты Ghidra, база 0x400000). Обязательны адрес и `.bytes` (не меньше 8 байт, из них не меньше 5 без масок `??`); хук ставится, только если байты совпали с памятью. Необязательные подключи: `.name`, `.args`, `.this`, `.base`, `.fields`, `.dump`, `.dumpfrom`, `.role` (подробно в `ds3probe.cfg.example`). Так новая гипотеза проверяется без пересборки DLL.

Ловец писателей: `WatchN = <abs|ctrl|camblock> <смещение> <w|rw>` (до 4), включается F3. Пишет в лог адреса инструкций, которые пишут или читают слово, со стеком вызовов.

## Запись и анализ

F7 начинает захват, F8 заканчивает. В папке сессии появляются:

| файл | содержимое |
|---|---|
| `ds3probe.log` | лог, строки `1s:` раз в секунду, итоги захватов, статистика F4 и AimLinear |
| `ds3probe_cap_NNN_di.csv` | кадры DirectInput-мыши: отсчёты до и после подмены F9 |
| `ds3probe_cap_NNN_acc.csv` | курсорный путь `Mouse_GetState` (камеру не питает, для сверки) |
| `ds3probe_cap_NNN_stickv.csv` | `FUN_0040E680` (мышь как виртуальный стик) |
| `ds3probe_cap_NNN_sticks.csv` | `FUN_0040D820` (сглаживатель): `dt`, вход, выход, окно, клэмп, адрес вызывающего (`caller_hex`: `0073F407` земля, `00549F2E` прицел, `0054F806` невесомость) |
| `ds3probe_cap_NNN_trace.csv` | трассировщики: регистры, аргументы, поля |
| `ds3probe_cap_NNN_dump.csv` | дампы памяти (`TraceN.dump`) |
| `ds3probe_cap_NNN_marks.csv` | метки F5 |

В шапке каждого CSV условия опыта: версия, cfg, роли, указатели, статистика F4, `zerog_scale`.

Анализаторы (Python 3, без сторонних пакетов):

- `python tools\analyze_follow.py <папка сессии> [--cap N] [--pair N_F4вкл N_F4выкл]`: камера. `[V1]` закон смешивания и его коэффициент, `[V2]` отставание от цели, `[V3]` какие слова контроллера лежат на углах, `[V4]` сравнение пары захватов, `[V5]` вес смешивания по кадрам (видно, где F4 работал), `[V6]` что реально уходит в `SetTransform` (нужен датчик `BlendOut` из camdump-cfg).
- `python tools\analyze_di.py <папка сессии> [--axis x|y]`: ввод. `[A]` DI против курсорного пути, `[B]`/`[D]` режимы F9, `[C]` передаточная кривая «отсчёты в выход стика», `[E]` трассировщики, `[F]` модель сглаживателя и сколько съедает клэмп, `[G]` рывки, `[H]` ступени F11.
- `python tools\analyze_gain.py <папка сессии> [--cap N] [--min-out 0.05]`: усиление по осям. `k` (рад/с на единицу выхода сглаживателя) для обычной камеры и невесомости с разбивкой «земля / поверхность / множитель DS3Probe» и итоговым соотношением yaw/pitch, множитель разгона прицела M с корзинами без фильтров, положение ползунка по `sens@+17C` из лога. Нужны аргументы `ApplyRotDelta` (`Trace1.args = 2` или больше; в play-cfg по умолчанию 0).
- `tools/analyze_samples.py`: анализатор v3 (курсорный путь), заморожен, оставлен для старых записей.

## Скрипты Ghidra (`ghidra/`)

Все только читают базу и пишут отчёт `~/ds3_<имя>_..._<md5[:8]>.md`. Работают в Jython и PyGhidra; все отработали в настоящей Ghidra на базе `deadspace3.exe` 1.0.0.1. Отчёты лежат в файлах проекта.

| скрипт | что даёт |
|---|---|
| `DS3_Report.py` | xref, вызывающие и декомпиляция курсорного пути и настроек управления по профилю MD5 |
| `DS3_Hunt.py` | полнота анализа базы, строки по шаблонам (smooth, mouse, sensitiv), RTTI-классы камеры и ввода |
| `DS3_DiConsumers.py` | кто вызывает `GetDeviceState` для мыши и куда идут отсчёты |
| `DS3_CamChain.py` | цепочка камеры после сглаживателя, готовый блок трассировщиков с настоящими байтами |
| `DS3_Work91.py` | чувствительность (`DAT_011D3470`, кривая `FUN_0042EC90`), поля контроллера, TurnSpeed, константы, вызывающие |
| `DS3_Writers.py` | кто пишет заданные поля объекта (по адресам из ловца F3) |
| `DS3_Range.py` | дизассемблер и декомпиляция диапазона адресов (так разобран `FUN_0074D6F0`) |

## Сборка и проверки

Сборка только в GitHub Actions (`.github/workflows/build.yml`): Windows, MSVC, Win32 Release, C++23, статический CRT (`/MT`), safetyhook + Zydis в `include/`. SHA коммита попадает в лог. С v4.10 и для сборок из PR это голова ветки PR (раньше был тестовый merge-коммит GitHub).

Тот же workflow прогоняет самопроверки на синтетике: `tests/test_analyze_di.py`, `tests/test_analyze_follow.py`, `tests/test_analyze_gain.py`, `tests/test_analyze.py` и макеты API Ghidra `tests/mock_ghidra_di.py`, `mock_ghidra_cam.py`, `mock_ghidra_work91.py`. Локально: `python tests/<файл>.py`, код возврата 0 значит «всё сошлось».

## Как это устроено

```
мышь -> DirectInput (GetDeviceState из 00895AFE, c_dfDIMouse2)
     -> FUN_0040E680 (мышь как виртуальный стик, сырой стик = 0.032 на отсчёт)
     -> FUN_0040D820 сглаживатель: окно 1/30 с, выход = clamp(сумма, ±this[3]) / (T·30)    <- StickClamp, ZeroGYaw, LookPitch
     -> потребители по адресу возврата:
          0073F407 земля / магнитная поверхность: LookUpdate FUN_0073F310 -> ApplyRotDelta FUN_00721BD0
                   -> внешний кадр FUN_0074D6F0: смешивание с прошлым кадром (вес (1-ctrl[13C])·30·dt) -> SetTransform   <- FollowFix
          00549F2E прицел: ApplyRotDelta из 00552176 / 00552222 с множителем разгона M (yaw до 2, pitch до 4)           <- AimLinear
          0054F806 свободный полёт: свой контроллер, ApplyRotDelta из 0054FCC6 (a0 pitch, a1 yaw)
```

Усиление в рад/с на единицу выхода сглаживателя (линейно на всех скоростях): земля yaw 3.940 / pitch 1.833, магнитная поверхность 3.940 / 1.309, невесомость 1.8326 / 1.8326 (с `ZeroGYaw = 2.15` yaw 3.94), прицел 100°/с / 80°/с при M = 1.

Надёжность: адреса и байты всех хуков сверяются с памятью (профиль по MD5, якорь по экспорту `?Init@Mouse@Windows@EARS@@YAXXZ`); если что-то не совпало, этот хук не ставится, остальное работает. Хуки в exe ставятся через 1.5 с после загрузки `d3d9.dll`.

## Ограничения

- Только 1.0.0.1. Адреса возврата для невесомости и прицела (`0054F806`, `00549F2E`, `00552176`, `00552222`) зашиты в код, а не в профиль.
- AimLinear работает только при включённом F4/FollowFix.
- `LookPitch` один на землю и магнитную поверхность: с 2.15 на земле вертикаль равна горизонтали, на поверхности остаётся в 1.4 раза медленнее (1.309·2.15 = 2.81 против 3.94).
- Ползунок чувствительности в меню работает. Все записи до 2026-10-11 сделаны при 50: `general.txt` был только для чтения, и 27 откатывалось на 50 (вывод «ползунок не влияет» в v4.9.1 был ошибкой). Как ползунок меняет соотношение осей, ещё не замерено: `analyze_gain.py` по записи с `Trace1.args = 2` покажет это и положение ползунка (`sens@+17C`: 50 даёт 1.0).
- Захват держит записи в памяти до F8 (до ~400 тыс. строк на CSV, дампы до 60 тыс. записей по 1 КБ): длинные захваты с дампами расходуют сотни МБ 32-битного процесса.
